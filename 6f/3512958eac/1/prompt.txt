## Headline finding (changes the premise)

**This package does NOT make direct Graph API HTTP calls.** All WhatsApp I/O goes through the `@photon-ai/whatsapp-business` npm client, which is a **nice-grpc** client to Photon's own backend, not `graph.facebook.com`. There is no `graphPost`/fetch wrapper, and no Graph API version is pinned anywhere in the repo — the actual Graph calls (and their version) live server-side in Photon's `whatsapp-business-grpc` service.

- Credentials (`accessToken`, `appSecret`, `phoneNumberId`, `ClientOptions` at `.../dist/index.d.ts:1030-1047`) are passed as gRPC metadata; there is no phone-number-ID/token URL construction in this repo.

### Bottom line for implementing typing
A truly minimal, package-only change is not achievable because (a) this package speaks gRPC to Photon, not the Graph API, and (b) the `MarkReadRequest` proto has no typing field and core's `typing` content carries no wamid. Implementing real typing indicators requires: a proto/backend change to accept a typing indicator + inbound wamid, a new/extended method on the `@photon-ai/whatsapp-business` client, and a way for the send action to obtain the last inbound wamid for the space (core's `typing` content would need to carry a target, or the package would need to track last-inbound-per-space).
