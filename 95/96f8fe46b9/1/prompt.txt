### 5. How to author a new skill

No generator, no scaffolder, no skill-specific lint. The relevant checks:

- `apps/sim/scripts/check-block-registry.ts:243-282` (`bun run check:block-registry` path) only enforces that a catalog integration **has** a `BlockMeta` — it does not require `skills`.
- `bun run check:skills` / `skills:sync` = `scripts/sync-skills.ts`, which is for `.agents/skills/**` dev skills. **Unrelated.**
- Tests are per-block and opt-in, e.g. `/Users/qwerzl/Documents/Projects/sim/apps/sim/blocks/blocks/harmonic.test.ts:305-312` asserts `skills.length &gt;= 5` and name uniqueness. `photon_imessage.test.ts` currently asserts nothing about meta.

Authoring rules (`.agents/skills/add-block/SKILL.md:928-960`, `.agents/skills/validate-integration/SKILL.md:272-274`, `apps/sim/blocks/AGENTS.md:13`):
- **3–5 mainstream + 2–3 niche** skills
- kebab-case, ≤64 chars, unique, verb-led name; one-line description; markdown content with `# Title` + `## Steps` + an output section
- **every step must be grounded in an operation in `tools.access`**
- **must be sourced from real, documented use cases found online — never invented**
