# WhatsApp Cloud API verification report

## Critical architectural finding (affects ALL claims)

The SDK at `/Users/riceontopp/Developer/photon-ai/spectrum-ts/node_modules/@photon-ai/whatsapp-business/dist/index.js` is **not** a Graph API client. It is a gRPC/protobuf client (nice-grpc + `@bufbuild/protobuf`, see `dist/index.d.ts:1-2`) that sends camelCase proto messages to the Photon Spectrum relay; the relay — not this SDK — constructs the actual Meta HTTP payload. So "SDK maps X to Meta field Y" is true only up to the relay boundary. Notable wire-name differences the relay must translate: `previewUrl` → `preview_url`, `languageCode` (flat string) → `language: { code }`, `replyToMessageId` → `context: { message_id }`. The proto `fromJSON` decoders accept both camelCase and snake_case aliases (`preview_url` at index.js:3167, `language_code` at index.js:4493).

## Summary of risk flags for the planned fixes

1. Do not emit `language: { code }` or omit-vs-empty `components` distinctions at the SDK layer — the proto is flat `languageCode` + repeated `components` (empty = absent on wire).
2. Do not set `caption` on audio/sticker inputs; SDK won't stop you for audio, and Meta's error for it is undocumented.
3. Do not assume `contacts[]`/`contact` present on every inbound message.
4. Outbound voice-note flag is not expressible via this SDK version's `MediaInput`.
5. Unknown/expired `replyTo` degrades to a quote-less send per docs — safe to pass through.
